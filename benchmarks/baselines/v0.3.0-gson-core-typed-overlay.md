# Benchmark report — v0.3.0-gson-core-typed-overlay

- Repo: `google/gson` (pinned commit `dae37cf0fe12235b76fb09f01118a0a8c8823f42`, same as `v0.2.0-gson-core`)
- Scope: `gson/src/main/` (same scope as `v0.2.0-gson-core`)
- Status: **SKIP**

## Reason

A before/after core-scope comparison of the SCIP typed overlay against the
pinned Gson build requires either:

1. A `scip-java` binary, or
2. A Maven `semanticdb-javac` + `javac -Xplugin` build.

Both require network access this session could not complete in a reasonable
time. The `scip-java` v0.13.1 release asset (~86MB) was reachable but
downloaded at ~15-20 KB/s through this environment's proxy — over 40 minutes
in, still short of half the file, with the remainder projected to take
another 40-50 minutes. A from-scratch Maven build has the same constraint
(no pre-cached dependencies) plus Gson's own build reaching out to Maven
Central for its compile-time dependencies.

Rather than block the M3 delivery on either download completing, or fabricate
overlay numbers without a real SCIP index behind them, this benchmark is
explicitly marked **SKIP**. It is not folded into `v0.2.0-gson-core.json`/`.md`,
which remain the last measured baseline and are unmodified by this milestone.

The typed-overlay merge/idempotency/precision guarantees this benchmark would
otherwise spot-check at Gson scale are instead machine-verified at fixture
scale by `fabric verify --level m3` (CI-gated) and
`tests/test_typed_overlay.py`, against the bundled `tests/fixtures/m3typed`
fixture — see `docs/adr/0003-typed-overlay.md` for what that fixture does
and does not exercise.

## Retry instructions

Given a network path to GitHub Releases or Maven Central with reasonable
throughput:

```
SCIP_JAVA_BIN=/path/to/scip-java scripts/build_scip_fixture.sh   # sanity-check the pipeline first
# then, against a checked-out Gson working copy:
scip-java index --output gson/index.scip   # or the Maven semanticdb-javac path
fabric build gson/
fabric overlay scip --repo gson/ --index gson/index.scip
```

then re-run the `repoweaver.benchmark.runner` core-scope comparison the same
way `v0.2.0-gson-core` was produced, before vs. after the overlay step, and
replace this file with a `MEASURED` report.
